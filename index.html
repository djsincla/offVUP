The problem

VMware's planner is excellent, but it's built to be served over HTTP. You can't simply download a zip of it and send it to someone.

The scenario pages and the home page load their data with fetch() calls. Browsers block fetch() on file:// URLs as a security rule — so an unzipped copy opens, renders its shell, and then shows No components available where the entire upgrade plan should be.

It fails quietly. The page looks like it loaded. Nothing tells you the data never arrived.

What's new in 2026.10.22

VMware's October update still doesn't run from a downloaded zip: unmodified, 1 of its 16 pages works offline. This release brings offVUP up to date with it.

  • New VKS Upgrade Planner for vCenter, Supervisor, VKS and Kubernetes Releases is included and works offline.
  • Version-compatibility data on the home page (4 MB, new upstream) now loads offline.
  • More tracking removed. Upstream now reports every export and Jira copy, and the customer's VCF, NSX, Operations and Automation versions, to a third-party server. All of it is stripped.
  • Mermaid no longer bundled. Upstream replaced it with its own diagram code, so the zip now contains no third-party code.
  • Fixed a silent stale build. Refreshing upstream could fail and the build would quietly package the old copy. It now always builds from VMware's latest commit, or stops.
  • Versioned releases. Each release is named after the date of the VMware snapshot it contains, which is also stamped in the zip's README.txt.

What the build changes

Four changes, and nothing else. No planning logic or content is touched.

ChangeWhy
Inline the scenario JSON Embeds each page's data directly and drops the fetch() call. This is the actual file:// fix.
Load compatibility data as a script The home page's version-compatibility data ships as compat-data.js, loaded by a <script> tag, instead of being fetched.
Seed the Kubernetes matrix Upstream already embeds the VKS upgrade matrix in every page, but fetches it first. The build points pages at the embedded copy, and aborts if that copy is stale.
Remove the trackers Upstream reports page visits, every export and copy, and the customer's VCF, NSX, Operations and Automation versions to a third-party hits.sh server. All of it is stripped. It would also render as broken images offline.

How it works

One command. Python 3 and git are the only requirements.

  1. Clone and run

    Upstream is cloned automatically on first run and refreshed to the latest commit on later ones — you don't need to fetch it yourself. If the refresh fails, the build stops rather than packaging a stale copy.

  2. Pages are rewritten

    Data is inlined and the trackers are stripped. The build aborts loudly if upstream adds a fetch() it doesn't recognise or any tracker or external script survives — it won't hand you a silently broken zip.

  3. Ship the zip

    You get dist/VCF-Upgrade-Planner.zip, about 5 MB. Small enough to email. Or skip the build and download the latest from Releases.

# build it
git clone https://github.com/djsincla/offVUP.git
cd offVUP
python3 build_offline.py

# -> dist/VCF-Upgrade-Planner.zip  (5.2 MB)

What your customer does

Unzip it. Double-click index.html. It opens in their browser and works. Windows, Mac, and Linux, from the same file.

Keep the folder together. The pages link to each other and share local libraries, so moving index.html out on its own will stop it working. This is called out in the README the customer receives.

Verified, not assumed

The released zip is unzipped and every page opened from a real file:// URL with the network blocked, in Chrome, Firefox and Safari's WebKit engine. All 16 pages load their data in all three, and selections made on the home page carry through to the scenario pages.

The same test against VMware's own zip is what proves the fix: 1 of 16 pages works. The rest render No components available or come up without their data.

Honest limitations

External links still need internet. The planner itself runs fully offline, but some pages link out to Broadcom documentation and the VMware Interoperability Matrix, and a few embedded doc topics show images hosted online. Those won't load on an isolated network. The planning tool works regardless.

It's a snapshot. VMware updates the live planner regularly; a zip stays at the version it was built from. Check the version above against your customer's copy and send a fresh one when it changes.
